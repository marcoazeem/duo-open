# Порт Duo Open на Microsoft Surface Duo 1 (Android 12L)

Статус на 21.10.2026: порт сделан, проверен на устройстве (см. «Что проверено»).

## Устройство (измерено через adb 21.10.2026)
- Surface Duo, `Build.MANUFACTURER=Microsoft`, `Build.DEVICE=duo`, **API 32** (Android 12L), сборка 2022.902.48.
- Один логический дисплей 0: 2784x1800 в ландшафте, оба экрана 1350x1800 рядом, 60 Гц, плотность 400.
  Зазор шарнира: полоса x = 1350..1434 (84 px), центр x = 1392 = половина ширины.
  Панели не переключаются; при закрытии дисплей выключается.
- Датчик шарнира: стандартный `android.sensor.hinge_angle` (Microsoft), on-change, **непрерывный**
  (resolution 1e-5), диапазон 0..360 (больше 180 = экран отогнут назад, работает один экран).
- GPU: Adreno 640, OpenGL ES 3.2.
- Размытие окон SurfaceFlinger включено (`ro.surface_flinger.supports_background_blur=1`),
  режим Live blur работает.

## Что сделано
1. `minSdk` понижен до 30. Все вызовы API 31+ закрыты проверками `SDK_INT`;
   `lintFullDebug` и `lintLiteDebug` не находят NewApi/InlinedApi.
2. Шейдер: на API 33+ остался AGSL без изменений (`fold/AgslFold.kt`). Ниже 33 работает порт
   на GLSL ES 3.0 (`res/raw/duo_unfold_gles.frag`) через `fold/gl/GlFoldRenderer.kt`
   (свой GL-поток, EGL14). Униформы считаются один раз в `DuoShader.uniforms()` → `FoldUniforms`.
   Файлы `.agsl` и `_gles.frag` надо держать синхронными.
3. Все три рендера на API < 33:
   - оверлей: `TextureView` в половинном разрешении внутри `FoldOverlayView`;
   - живые обои: GL рисует все кадры в `Surface` обоев, фаза сгиба в половинном разрешении (FBO);
   - превью в приложении: GL размывает только картинку фона, часы и карточки остаются чёткими.
   При сбое GL везде показывается обычная картинка.
4. Профиль двухэкранного устройства (`fold/DeviceProfile.kt`): Surface Duo 1/2 или
   `adb shell settings put global duoopen_test_dual_screen 1`.
   - Дисплей 0 всегда «внутренняя панель» (по соотношению сторон 1.55 он считался бы внешним).
   - По умолчанию движутся обе половины (`movingSide = 0`), линия сгиба по центру длинной стороны.
   - `PanelEngine`: поза, в которой экран включился, считается покоем; эффект запускается,
     когда шарнир уходит от неё на 1° наклона (~5–6° угла при движении обеих половин),
     гаснет через ~1 с после остановки и снова взводится с новой позы.
   - `HingeAngleSource` принимает 0..360 от стандартного датчика; больше 180 = ровно.

## Что проверено на устройстве
- Сервис видит один дисплей: `engine display=0 inner=true ... dualScreen`.
- Датчик непрерывный (`res=1.0E-5`), не stops-only.
- Live blur: демо (`am broadcast -a com.duoopen.DEMO`) проигрывается.
- Snapshot через GL: реальное складывание запускает эффект (`leaving rest ... showing 2784x1800
  snapshot (capture 86ms)`), остановка гасит его, следующее движение запускает снова.
  На скриншоте края размыты и затемнены, у шарнира чётко, по углам перспектива.
- Превью в приложении: при 127° края фона размыты (проверка FBO-пути половинного разрешения).
- Обои: в окне предпросмотра живых обоев при ~105° верх размыт. Обои пользователя не менялись.
- Собираются `assembleFullDebug`, `assembleLiteDebug`, `assembleRelease`.

## Что не проверено
- Регресс на Android 13+ (OnePlus Open, Fold 8): устройства и эмулятора не было.
  Код AGSL только перенесён, логика не менялась, но проверить надо.
- Портретный режим на два экрана (дисплей 1800x2784, сгиб горизонтально на y = 1392).
- Lite-сборка на устройстве (код обоев общий с full).
- Shizuku: быстрый захват использует скрытые классы новее Android 12L и должен откатываться
  на скриншот доступности; на Duo не запускался.
- Частота кадров GL при складывании не измерялась.

## Известные ограничения
- Превью в приложении на API < 33 размывает только картинку фона, не весь интерфейс.
- Если приложение открыто на одном экране, `FoldingFeature` нет, и превью ставит сгиб
  по центру своего окна. Оверлей и обои это не затрагивает.
